# CapsuleCraft v2.5.0 — pictures on the board

The second half of the page-mode story lands: **the canvas can hold
pictures**. Every diagram now reaches into the capsule it lives in —
screenshots from the mail, images pasted into the page — and onto the
board, next to the sticky notes and shapes.

## Image nodes

The canvas toolbar gains **«Картинка»** (`Icon::Image`). One click lists
the pictures already in the capsule plus «Выбрать файл…»; a file pick
runs through the same dialog and the same cid rule as the image block —
the cid derives from the bytes, so picking the same picture twice reuses
one attachment instead of stacking copies. The bytes live once in
`capsule.attachments`; the node stores only the reference (`cid`), the
same scheme every other canvas element uses for its own data.

The new node spawns at the visible center of the field (the v2.4.1
rule), resizes and drags like any other node, snaps to the grid,
marquee-selects, and serves as an arrow endpoint.

## Rendering and viewing

The picture letterboxes into its node rect — aspect kept, centered —
via a pure `fit_inside` helper. An element whose cid does not resolve
draws a quiet placeholder (icon + «Изображение не выбрано» or «не
декодируется») instead of a blank box. Double-clicking a picture opens
the full-screen viewer.

Both entry points share the capability: the block-level canvas and the
page mode («Страница | Канвас») apply the same operations now — new
attachments are upserted by cid, and viewer requests reach the shell.

## Tests

- Factory defaults: 180×120, no text.
- cid resolution: the `cid:` prefix is stripped, non-image MIMEs don't
  match, missing attachments don't panic.
- Letterbox math: aspect preserved, centered, degenerate sizes fall
  back to the whole bounds.
- Headless draw of both paths — a real 8×6 PNG built in the test, and
  the unresolved-cid placeholder.

Native suite: 259 → **263** passed, 0 failed, 2 ignored.

## Upgrade

Usual paths: the AppImage, the `.deb`, the macOS universal `.dmg`, the
Windows NSIS installer or the portable zip. `.eml` capsules stay
compatible: an image node is one more element in `page-canvas.json` /
the canvas block data, referencing attachments that were already part of
the format.
