# CapsuleCraft v2.2.1 — the editor keeps its promises

This one is a debt-release: three things the interface already promised and
one affordance it owed since the grip appeared. No new storage, no schema
changes — the `.eml` capsule format is untouched, and everything ships in
the native editor (`native/src/blocks/mod.rs`,
`native/src/views/document_view.rs`).

## What was promised

The page editor already had three broken promises in it:

1. The grip menu offered exactly one insertion — «вставить изображение
   ниже» — while the bottom-of-page «+» button knew all ten block kinds.
2. The hint under every page said «„/“ в пустом абзаце открывает блоки»,
   and grep confirmed no handler anywhere consumed a slash.
3. Blocks could only be moved with «Выше» / «Ниже» menu rows, one step at
   a time, while the grip icon sat there looking draggable.

All three closed in this release, plus a fourth affordance Notion has made
reflexive.

## The insert-below palette

The block palette itself is now one source of truth,
`block_kind_items()` — the same ten `(icon, label, kind)` rows feed the
bottom «+» menu, the grip menu, the gutter «+» and the slash menu. In the
grip menu the old single image row became a «Вставить ниже ▸» section that
expands on hover, the way native submenus do. Hover, not click: a click
inside a `Popup::menu` closes the whole popup, so the toggle had to stay
clickless; the expanded list keeps itself open while the pointer is over
any of its rows and collapses the moment the pointer moves below. Choosing
a kind emits the existing `BlockOp::InsertBelow(kind, "")`, which the
document view already handled — the feature was half-built infrastructure
waiting for a menu.

## The gutter «+»

Next to the grip (which shrank from 20 px to 14 px wide to make room) a
small «+» appears on row hover. It opens the same palette and inserts
directly below the hovered row. The button is allocated only while the row
is hovered, so the gutter contains no invisible hit-targets when idle, and
it hides entirely while a drag is in flight.

## The slash menu

Typing «/» in a paragraph opens a floating palette anchored under the
block — `Area` at `Order::Foreground` with the popover frame, the same
pattern as the selection bubble toolbar. Whatever follows the slash filters
the palette live: the match checks the localized label and the English one,
so in the Russian UI both «врез» and `/callout` find «Врезка». Selecting a
kind clears the slash text and converts the paragraph in place through
`BlockOp::TransformTo` — an empty `/todo` becomes an empty task list, and
the block keeps its id. The menu closes when the slash disappears (deleted
by hand or consumed by the selection), when the block loses focus to
another text field, or when Enter introduces a newline. The filter is a
pure function, `slash_matches(query, locale)`, unit-tested against both
locales.

Keyboard selection (arrows + Enter) is deliberately out of v1: the
TextEdit owns those keys while focused, and stealing them breaks caret
movement. Click-to-choose covers the promise; arrow-key navigation is a
follow-up.

## Drag-and-drop reorder

The grip handle is now `Sense::click_and_drag()`. A short press still
opens the menu; a press that moves starts a drag. The drag state — which
row grabbed (`from`) and where the insertion line sits (`to`) — lives in
egui temp memory under one id, because rows are rebuilt from fresh clones
every frame. While the drag is live, every row checks whether the pointer
is over it and halves its rect: top half means «insert above me», bottom
half means «below me». The row the gap touches draws the accent insertion
line with a dot at its left end, and the cursor becomes a grabbing hand
for the whole window, not just over the handle.

On release the row that started the drag emits `BlockOp::Reorder { from,
to }`. The index math is isolated in `reorder_insert_index(from, to, len)`
— a pure function returning the post-removal insert index or `None` for
no-op — so the document view stays a dumb executor and the edge cases are
unit-tested: the same gap and the gap one below the block are no-ops,
`from` below `len`, `to` beyond `len`, and moving up or down across
several rows all behave as the insertion line promised.

One documented trade-off: dragging is index-based, and the skipped
duplicate-H1 block (when the page subject repeats the first heading) is
never rendered, so its grip does not exist — the same is true of its menu,
which was already the case.

## Version sync

The v2.2.0 bump had moved only `native/Cargo.toml`; `src-tauri/Cargo.toml`,
`src-tauri/tauri.conf.json` and `package.json` were left on 2.1.0. All four
manifests (plus both lockfiles) now say 2.2.1, so release filenames and the
About badge agree again. The grip tooltip also stopped lying: it said
«Добавить блок» while the handle's menu never added anything on its own —
it now reads «Меню блока — тяните, чтобы переставить».

## Tests

`cargo test` in `native/`: **233 passing** (was 230). New: two tests for
`reorder_insert_index` (index math and a remove/insert simulation matching
the document view), one for the slash filter (empty query, Cyrillic
prefixes, English fallback inside the Russian locale, no matches). The
pre-existing i18n purism tests cover the four new keys
(`InsertBelow`, `SlashMenuTitle`, `SlashNoMatches`, `BlockGripHint`) and
the removal of the single-purpose `ImageInsertBelow` key.

## What this sets up

The canvas flagship (page mode «Страница | Канвас», pan/zoom, arrows,
flowchart shapes) is v2.3; vector drawing inside the canvas is v2.4. This
release only touches the row/menu layer those features will reuse — the
palette and the row hover machinery are the two seams the canvas page
mode will hang from.
