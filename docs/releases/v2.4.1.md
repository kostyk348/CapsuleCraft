# CapsuleCraft v2.4.1 — the button's result is always on screen

A small, sharp patch release: the canvas toolbar's add buttons («Стикер»,
«Текст», «Фигуры», «Страница») used to place every new element at a fixed
spot near the world origin — `24 + (index%6)*18`, both axes. The viewport
persists in `data.view`, so the bug surfaced exactly when the board had a
reason to look elsewhere: after panning away, after «Вписать» on content
far from the origin, or on a page whose saved view was restored. The click
"worked" — the element was added, undo knew about it, the file was marked
changed — it was just drawn outside the visible field. On a fresh canvas
it showed, after a pan it vanished: «при добавлении через кнопку
нестабильно показывает».

## Fixed

- **Toolbar adds spawn at the visible center** (`native/src/blocks/canvas.rs`):
  the new element lands at `view.screen_to_world(canvas_rect.center())` —
  the middle of what the user is actually looking at — with a small
  cascade (+16 world px per consecutive add, the Excalidraw/Figma trick)
  so eight quick adds fan out instead of stacking.
- The draw pass publishes the canvas rect to egui memory under
  `("canvas-rect", block_id)`; the toolbar reads it back at click time.
  Widget order inside the frame no longer matters, and the hand-off is
  testable headlessly.
- The element factory became `canvas_element_at(kind, at, locale)`; the
  legacy fixed-position `canvas_element(kind, index, locale)` wrapper is
  gone, and the `blocks::canvas_element` re-export updated accordingly.

## Tests

- `spawn_lands_in_the_visible_field` — four views (identity, panned
  −5000/−3000, zoomed out 0.5, zoomed in 2.0) × twelve consecutive adds:
  the spawn rect always intersects the viewport's world rect.
- `consecutive_spawns_cascade_but_stay_close` — cascade never stacks two
  adds exactly and never drifts further than one node size from the
  center.
- `draw_pass_publishes_the_canvas_rect` — a real headless draw pass must
  leave the rect where the toolbar expects it.
- `factory_builds_at_the_given_position`, `page_element_factory_produces_a_node`
  — updated to the positioned factory.

Native suite: **259 passed, 0 failed, 2 ignored** (v2.4.0 shipped 255).

## Upgrade

Usual paths: the AppImage, the `.deb`, the macOS universal `.dmg`, the
Windows NSIS installer or the portable zip. No data migrations —
`.eml` capsules and canvas parts are unchanged; only where new elements
appear moved.
