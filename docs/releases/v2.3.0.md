# CapsuleCraft v2.3.0 — the canvas

This release is the one v2.2 promised: the whiteboard inside every page is
no longer a flat board of sticky notes. It is an **infinite field** you pan
and zoom over, and it now speaks the language of diagrams — **arrows,
decision diamonds, terminator blocks, labels, grid snapping, minimap**. The
`.eml` capsule format is untouched: an arrow is three JSON fields, a node is
the same flat record it always was.

Two PRs built the canvas (engine #40, flowchart #41) and one fixed the
Integrations modal where the «свои модели» buttons drifted off their cards
(#42).

## The infinite field

Everything on the board now lives in world coordinates behind one
transform (`screen = world × zoom + offset`):

- The wheel pans the field — and claims the scroll while the pointer is
  over the canvas, so the page behind it stays perfectly still. Ctrl+wheel
  and pinch zoom between 0.2× and 4×, anchored at the cursor; the anchor
  survives the clamp, so zooming into the limit never shifts the point
  under your hand.
- The grid re-pitches one ladder step per octave of zoom, keeping its
  screen spacing between 28 and 57 px — the field looks the same at 20% as
  at 400%.
- The marquee, the rubber band of a dragging arrow and the minimap are all
  world-space, so selection stays honest at any zoom.
- «Вписать» (fit) recomputes the view from the content bounding box; the
  viewport persists in the capsule and survives restarts.

## Arrows

A selected node grows a small connector port on its right edge. Drag from
it, drop on another node — an arrow appears. The drafting rubber band
follows the cursor, and the drop only lands on a real node, so no dangling
lines are possible.

An arrow stores only `from`, `to` and an optional `label`. Its endpoints
are recomputed from the node rectangles **every frame**: move a node and
its arrows follow for free; undo a move and the arrows come back with it.
Connectors exit through the shape's actual border — the ray-to-rect
intersection for rectangles and stickies, the exact L1 edge for diamonds —
and land with a filled arrowhead. A label sits on the midpoint with a
background halo, readable over any content.

Click near a segment to select an arrow; press Delete to remove it.
Deleting a node prunes every arrow that pointed at it, so no ghosts. Undo
covers arrow creation, moves and deletes like any other edit.

## Text you can finally edit

An old debt closed here too: canvas text existed but could never be edited.
Double-click a node — or an arrow — and an inline editor opens right on the
element. Focus arrives once (no fighting with the click that opened it),
Escape or clicking away saves and closes.

## Flowchart shapes, snap, minimap

- **Ромб** and **Скруглённый** (terminator) join the sticky and rectangle,
  with toolbar buttons and their own connector geometry.
- The **«Сетка»** toggle (persisted) makes group drags land on a 20-unit
  grid — half the zoom-1 pitch, always aligned with the visible lines.
- The **minimap** appears bottom-right once two or more nodes exist: the
  content box, every node as a rectangle, the current viewport outlined in
  accent — click or drag inside it to jump across a large board.

## Integrations: the drifting buttons

The reported bug: in Integrations, the bottom «Подключить свои…» rows have
two right-aligned buttons («Выбрать папку», «Убрать»), and with a real
folder path they visibly drifted off the card. The cause was one missing
clamp: `hud()` — the tiny uppercase label used all over the app — laid its
text out with no width limit and allocated the galley as-is, so a deep
folder path stretched the card frame past the viewport and dragged
everything anchored to its right edge.

`hud()` now re-layouts with a trailing `..` when the line does not fit its
available width. The clamp is binary-searched (one extra layout pass only
when the line actually overflows), and it fixes the same latent overflow at
every other hud call site: requirement lists, file sizes, attachment names,
mail headers. The Integrations dialog itself is additionally clamped to the
window, so short viewports can no longer clip its right edge.

## Screenshot tooling

The deterministic `--snapshot` mode gained two flags: `--modal integrations`
opens a dialog on startup, and `--window-size 980x640` targets the app's
minimum window — dialogs can now be captured for README and visual
regressions without window-manager automation.

## Tests

`cargo test` in `native/`: **248 passing** (was 233). The new suite covers
the world/screen round-trip, anchored zoom under clamping, corrupt-view
fallbacks, fit-view bounds, the grid ladder, rect and diamond anchors, edge
hit-testing with endpoint clamping, dangling-arrow pruning, the arrow-free
bounding box, topmost-node hits, snap rounding, the hud width contract and
row/button containment under a 140-character path. CI runs the suite with
`-j 1`, verified stable twice.

## What this sets up

The canvas is still a block on the page. The next stop is the page-mode
switch («Страница | Канвас» in the document header) — a full-page canvas
whose nodes can link to other pages through the existing wiki-links, with
image and audio nodes fed by Content-IDs. The engine, the arrows and the
shape system in place are exactly the seams that feature hangs from; vector
freehand drawing comes after that.
