# v2.12.4 — Android запускается

Дата: 2026-11-08. Ветка: `fix/android-libcxx-launch`. Чинит: вылет Android-приложения
при запуске (все версии до этой включительно).

## Диагноз

Статический аудит ELF-таблиц релизного APK v2.12.3
(`scripts/check_apk_native_deps.py`): у `lib/arm64-v8a/libcapsuleos_native.so`
среди `DT_NEEDED` есть `libc++_shared.so`, но в APK упакованы только три
нативные библиотеки — самой `libc++_shared.so` нет. Loader на устройстве
резолвит зависимости `dlopen`'a eagerly → библиотека не находится → процесс
умирает до первого байта Rust-кода. Это случилось на любом устройстве.

Откуда зависимость: cpal под Android использует oboe — C++-библиотеку, она
линкуется с рантаймом `libc++_shared.so`. cargo-ndk собирает `.so`, но эту
рантайм-библиотеку из NDK в `jniLibs` не копирует (известная особенность —
он рассчитывает, что это делает сборка gradle/NDK-проекта).

Что при этом было в порядке: выравнивание `PT_LOAD` — 16384 (16 КБ-устройства
не проблема), `ANativeActivity_onCreate` и `android_main` экспортированы,
бэкенд `android-native-activity` соответствует `NativeActivity` из манифеста
(это чинили в v2.12.0 — тогда вылет был по другой причине; теперь открылась
следующая).

## Чин

- `android.yml` и `release.yml`: после `cargo ndk` новый шаг копирует
  `libc++_shared.so` из sysroot NDK
  (`toolchains/llvm/prebuilt/linux-x86_64/sysroot/usr/lib/aarch64-linux-android/`)
  в `android/app/src/main/jniLibs/arm64-v8a/`.
- Новый гейт `scripts/check_apk_native_deps.py` (чистый python, без SDK)
  прогоняется по собранному APK в обоих воркфлоу: каждая `DT_NEEDED`
  зависимость каждого упакованного `.so` должна быть системной или
  упакованной; `PT_LOAD`-выравнивание ≥ 16384; экспорт
  `ANativeActivity_onCreate` на месте. На APK v2.12.3 гейт падает, на
  исправленном — проходит (проверено локально).
- `versionCode` поднят с навсегда застрявшего `1` до `2` — без этого новая
  сборка не ставилась поверх старой («Приложение не установлено»).
- `docs/android.md`: актуальный бэкенд (`android-native-activity`) и раздел
  про `libc++_shared.so` + гейт.

## Проверка

- Локально: чекер на релизном APK v2.12.3 → `BROKEN` (exit 1, FAIL по
  `libc++_shared.so`); на эмуляции исправленного APK → `LAUNCH-READY`.
- CI: android.yml собирает debug APK и гоняет гейт; релизная сборка по тегу
  v2.12.4 прогоняет гейт по подписанному APK до загрузки в релиз.
