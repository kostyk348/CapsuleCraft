# CapsuleCraft v2.0.0 — Project Knowledge Engine

Your codebase, turned into a local knowledge base of `.eml` pages — with agent
skills generated from it. This is the 2.0 line: the native shell is the
product, everything runs offline, and the vault is still just a folder.

## The headline: Project Knowledge Engine

Point CapsuleCraft at any source tree and it becomes a browsable knowledge base
inside the same vault you already use:

- **Incremental scan** (`.capsule/.index_state.json`, FNV-1a + mtime + size):
  re-scanning 500+ unchanged files takes well under 30 ms, and renamed or
  deleted files lose their stale capsules instead of leaving orphans.
- **Signature + docstring parsing** for Rust, TypeScript/JavaScript, Python,
  Go, C#, Java, Dart and Markdown documentation: multi-line declarations,
  generics, return types, `///` / `//!` / JSDoc / Python docstrings.
- **Technical-debt registry**: every `TODO`, `FIXME`, `BUG:`, `HACK:`,
  `NOTE:` lands in `.capsule/tasks_todo.eml` with file and line.
- **Hierarchical output**: `index.eml` (overview + metrics), `subsystems/`,
  `modules/`, `docs/` — cross-linked with `[[wiki links]]`.
- **Zero data loss on re-sync**: blocks, tags, status and the whiteboard
  `canvas_state.json` you added by hand survive every regeneration
  (`write_capsule_preserving`); the old flat layout migrates automatically.
- **Agent skills**: the scan emits skill scaffolding and MCP wiring so an
  autonomous agent opens the project with context instead of guessing
  (`native/src/project_skill.rs`, `docs/PROJECT_KNOWLEDGE_ENGINE.md`).

## Also in 2.0

- **Folder folding in the sidebar** — one click collapses or expands every
  subfolder (`modules/`, `subsystems/`); `index.eml` stays open, nested
  folders start collapsed so a 500-file repo is not visual noise.
- **Integrations carry over from 1.12**: local OCR (Xiaomi-OCR-0 on the
  pure-Rust mistral.rs engine), whisper STT in-process on candle, Russian
  piper voices through sherpa-onnx, pdfium PDF viewer and the image viewer —
  all downloaded from ⚙ Integrations, never bundled.
- **Native-only artifacts** for all three desktops: Windows `setup.exe` +
  portable zip, Linux AppImage + `.deb` (built on ubuntu-22.04 for a glibc
  2.35 floor), macOS universal `.dmg`. One `SHA256SUMS.txt` per release.

## Verified in this release

`cargo check`, `cargo fmt --check` and `cargo test` on the native shell, plus
the web engine's typecheck/vitest/build — the same gates that must pass before
the release job is allowed to publish (an incomplete artifact set leaves the
release as a draft rather than shipping half of it).

## Known gaps, on purpose

Honest list, tracked in `LIMITATIONS.md` and scheduled for **v2.1.0**:
PDF pages that render blank or report a re-bind error after the inline preview
has already loaded pdfium; images only land as attachments at the end of a
page instead of where the cursor is; OCR only accepts raster attachments (no
PDF pages); and TTS/STT ship Russian voices only, with no way to point the app
at your own models. All four are the next release, not "someday".
