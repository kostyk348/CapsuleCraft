# CapsuleCraft v2.1.0 — PDF, images, OCR, English voices

Every gap that v2.0.0 named in its "known gaps, on purpose" section is closed
here: the PDF viewer renders, an image goes exactly where you insert it, OCR
starts and answers, and TTS/STT speak English — with your own model folders
accepted when you already have them on disk.

## PDF pages actually render

The viewer died on every PDF with *"pdfium … already initialized"* — the inline
page preview and the full-screen viewer each bound the pdfium library, and
`pdfium-render` 0.9 refuses a second bind in one process. The viewer lost that
race by construction, so it showed an empty page with a renderer error.

- New `native/src/pdf.rs`: **one binding per process**, cached in a
  thread-local (every pdfium call the app makes is on the UI thread, and
  `Pdfium` itself is not `Sync`, so a `static` would need an `unsafe impl` we
  do not want). Idempotent by construction: the second caller gets the same
  engine instead of `PdfiumLibraryBindingsAlreadyInitialized`.
- Inline previews and the viewer now share that engine, so preview → open no
  longer breaks anything.
- If the library is genuinely missing, the message names the path instead of a
  generic render failure.

## Images where you want them

New **image block** (`native/src/blocks/image.rs`, type `image`):

- **Block menu → "Вставить изображение ниже"** inserts a picture directly
  below any block — the page is no longer append-only.
- **Block → Image** in the add menu, then *Choose file…* (`png`, `jpg`, `gif`,
  `webp`, `bmp`) or *From attachments* to reuse a picture already in the page.
- Width presets (25 / 50 / 75 / 100 % of the text column), a caption field, and
  a click that opens the full-screen viewer with zoom.
- Bytes live in `capsule.attachments` (one copy, same as audio); the block
  stores only `{cid, caption, width}`. Re-picking the same file replaces the
  bytes instead of duplicating them.

## OCR that starts, and reads PDF pages

Three separate faults, all fixed:

- **The engine was killed at spawn** by `-a qwen3_5`. The architecture flag only
  accepts the loader names of that exact engine build, and an unknown value
  aborts the process immediately — which the app could only report as "engine
  exited before readiness". The flag is gone: the engine reads `model_type`
  from the checkpoint's own `config.json`, which is version-proof.
- **The chat request used an invented model name** (`"model": "ocr"`). The
  endpoint only accepts the id advertised by `/v1/models`, so a perfectly
  healthy engine answered `model "ocr" not found`. The id is now read from
  `/v1/models` at startup and reused.
- **The readiness window was shorter than a cold start.** 1.75 GB of weights
  plus the vision tower on a laptop routinely exceeded five minutes; the limit
  is now 15 minutes for load and inference, and `--no-ui` keeps the bundled web
  chat off the local port.
- The viewer's OCR button is no longer image-only: for a PDF it renders the
  **current page at 2000 px** and sends that raster, so a scanned document is
  readable straight from the viewer.

## English TTS / STT, and your own models

- **Voice Amy (`en_US-amy`, piper medium)** joins Irina and Dmitri in
  Integrations. The voice is chosen from the page itself: a Cyrillic page gets
  a Russian voice, a Latin page the English one, and any installed voice is the
  fallback so one download is still enough.
- **STT language follows the app locale** instead of a hard-coded `<|ru|>`:
  English audio in an English UI is decoded as English, not as Russian-sounding
  gibberish (`whisper::Language`).
- **Custom model folders** — Integrations → *Своя модель*: point STT, TTS or
  OCR at a folder you already have. Every path is validated before use
  (`config.json` + weights for whisper and OCR, any `.onnx` + `tokens.txt` for
  a piper voice), a bad folder degrades to the catalog instead of failing at
  inference time, and changing the OCR model restarts the engine instead of
  silently keeping the old one.

## Verified in this release

`cargo check` and `cargo test -j 1` on the native shell (217 tests, 0 failed),
plus the src-tauri crate's `cargo check` / `cargo fmt --check` / `clippy -D
warnings` and the web engine's typecheck / vitest / build — the same gates that
must pass before the release job publishes. New unit coverage: pdfium singleton
behaviour, `serve_args` shape (no `-a`), `/v1/models` parsing, whisper language
tokens, custom-model validation, the image block, and the English voice's
tarball URL + sentinel name.

## Upgrading

Nothing to migrate: the vault is still a folder of `.eml` files, and settings
without `custom_models` load unchanged. If the PDF viewer failed for you on
2.0.0, just open the same document again — no re-download of pdfium needed.
