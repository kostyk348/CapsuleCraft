# CapsuleCraft v2.4.0 — the page becomes the canvas

The promise of v2.3 lands: the page-mode switch. Every page is now
**«Страница | Канвас»** — the familiar block editor on one side of the
toggle, and a full-height diagram on the other, powered by the v2.3
canvas engine. Alongside it, two reliability fixes: IMAP sync runs like a
service instead of freezing the interface, and the app's data directories
stopped having a mind of their own.

## «Страница | Канвас»

The document header gains a two-button toggle. «Страница» is the editor
you know; «Канвас» replaces the block list with one full-height canvas —
pan and zoom, arrows, decision diamonds and terminators, grid snapping,
the minimap — all of it already shipped in v2.3, now applied to a whole
page.

Storage stays honest to the format: the diagram persists inside the same
`.eml` as a `page-canvas.json` JSON part — the `canvas_state.json`
mechanism generalized. No schema changes, no sidecar files; pages without
a canvas parse exactly as before, and the part never shows up as an
attachment. The toggle itself is per-page view state, not capsule
content: the diagram is the page, the switch is just a lens.

## Page nodes

The canvas gains a new element: a **page node** — a wiki-link in
disguise. It renders with an accent border, you type a page title on it,
and clicking an already-selected node opens that page through the
existing title resolution. A title that matches nothing offers to create
the page — exactly the flow of a clicked `[[link]]`. A design sketch on
Monday can become the page it deserves by Friday without ever leaving
the board.

## Sync without the freeze

Three fixes to IMAP sync («Синхронизация почты»):

- **The UI thread is no longer a network client.** v2.3 ran the whole
  round-trip — TLS connect, folder scan, body fetches — inside a frame,
  freezing the interface for seconds to minutes on real mailboxes. Sync
  now runs in a named thread and reports back through a channel, the
  same idiom as the OCR engine.
- **No more duplicate floods.** Downloads were named
  `capsule_imap_{uid}.eml` and matched only by file name: a folder reset
  (new UIDVALIDITY) collided silently and blocked re-downloads forever,
  while already-uploaded capsules without an envelope Message-Id were
  appended to the vault again on every sync. Bodies are now
  content-hashed before writing, and downloads carry the normalized
  Message-Id in their name. Skipped messages are reported honestly:
  «+2 downloaded, +1 uploaded, 3 already in sync».
- **auto_sync finally works.** The flag was stored and never read. It
  now syncs once shortly after startup and every 15 minutes while
  enabled; manual «Синхронизировать сейчас» is unchanged.

## Data directories you can point at

The «положение OCR моделей» class of bugs is closed. The old last resort
of `app_data_dir()` was a **relative** path — with no `HOME` in the
environment (exotic launchers, stripped containers), the 1.75 GB OCR
model and the component catalog resolved against the process CWD: an
AppImage started from different folders wrote them to a different place
on every launch and re-downloaded next time. The fallback is now an
absolute path, and two overrides make portable setups explicit:

- `CAPSULECRAFT_DATA_DIR` — components, models, vault pointer;
- `CAPSULECRAFT_CONFIG_DIR` — theme, zoom, custom model folders.

README documents both roots and the overrides.

## Tests

`cargo test` in `native/`: **255 passing** (was 248). New: page-canvas
round-trip, page-node factory, headless full-page canvas draw, download
naming across folder resets, filesystem-safe names, body digests, and
the data-dir priority chain. CI runs `-j 1`.

## What this sets up

Image and audio nodes on the canvas (fed by Content-IDs) are the
remaining half of the page-mode story, then vector freehand drawing. The
storage, the toggle and the node plumbing in place are the seams those
features hang from.
