# v2.12.1 — планировщик держит слово

Дата: 2026-11-08. Ветка: `feat/v2.12.1-planning-fixes`. Патч-релиз по баг-репорту
пользователя: «опять сломан драг-энд-дроп, задачи не создаются нормально,
релоадится и удаляется, отметить выполненной нельзя, сразу показывает OverDue».

## Корневая причина — одна на большинство симптомов

Шелл сохранял **только открытую страницу** (`record_change` + `save_selected`
работают с `self.selected`), а планировщик правит #inbox-страницу — не
обязательно открытую. Итог: галочки и переносы слетали при перезапуске или
при любой перезагрузке хранилища watch'ером; созданные задачи исчезали.

1. **ViewAction::touched** — вид возвращает индексы изменённых капсул; шелл
   (`persist_touched`) сохраняет каждую из них с undo-снимком и статусом
   «Saved». Драг задачи в календаре (Edit::Patch) и переключение галочки
   (Edit::Toggle) теперь доходят до диска.
2. **add_task** выбирает цель: native #inbox → любой native → **создаёт
   новую страницу** ( subject «Tasks», тег #inbox). Было: первый капсула,
   даже read-only импорт — запись падала, задача жила только в памяти.
3. **Поле даты** пересобиралось каждый кадр из клонированного item, поэтому
   любой незавершённый ввод («2026-») отбрасывался и поле «дралось» с
   клавиатурой. Теперь черновик живёт в `PlanningState::due_drafts` и
   коммитится, как только дата полная (или по потере фокуса); невалидный
   текст красный, красный overdue-тинт следует вводимой дате.
4. **Подсказка календаря**: если фокусный день в прошлом, панель дня явно
   пишет, что новая задача сразу попадёт в «просрочено» (ключ i18n
   `PastDayHint`, RU/EN).

## Известное

- Сайдбарный драг-энд-дроп страниц (reparent) не менялся: он сохраняет
  капсулу сам (`reparent_page`) и работал. Если у пользователя «не работает»
  именно перетаскивание страниц дерева — нужен отдельный репро.
