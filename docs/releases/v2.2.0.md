# CapsuleCraft v2.2.0 — themes, accent, onboarding

Two things this release is about: the app learns to **look like you**, and it
learns to **introduce itself**.

## Obsidian-style theming

`native/src/theme.rs` is rebuilt around a preset table. Instead of two hand-
maintained palettes there are now **eight complete themes**, each with its own
background, panels, controls, chrome, ink, accent and status colours:

| id | name | base |
|---|---|---|
| `dark` | Graphite (default) | dark |
| `light` | Paper | light |
| `nord` | Nord | dark |
| `gruvbox` | Gruvbox | dark |
| `catppuccin` | Catppuccin Mocha | dark |
| `solarized` | Solarized | light |
| `everforest` | Everforest | dark |
| `rose` | Rosé Pine | dark |

Implementation notes:

- Every surface/text/status colour is explicit per theme. The derived
  translucency slots — `muted`, `dim`, `faint`, `line`, `line_strong`, `wash`,
  `wash_selected`, `wash_hover` — are computed from the theme's `ink` and its
  dark/light base, so **adding a ninth theme is one table row**.
- **Accent override**: the user can layer a personal accent colour over any
  preset (Obsidian's model). It survives theme switches, and `accent_ink`
  derives a readable companion tint per base (lifted toward white on dark
  bases, toward black on light ones).
- **Font scale** 80–140 % is applied to every text style in `apply()`.
- **Persistence** in `native-appearance.json` (theme id, accent RGB, font
  scale) next to the locale setting; the legacy `native-theme.txt` from the
  first theming iteration is still honoured, so nobody's light/dark choice
  resets.
- The **Appearance picker** (`native/src/modals/appearance.rs`, new) lives in
  ⌘K as «Внешний вид / Appearance»: theme cards painted with each theme's real
  swatches, accent chips with a reset-to-theme chip, and the scale slider.
  Every change applies to the live window immediately and persists on the spot.
- The old «Переключить тему / Toggle theme» command still works — it now
  flips between the two base presets.

## The interactive onboarding tour

New `native/src/modals/onboarding.rs`: **12 bilingual steps** (RU/EN — every
title, body and button; an EN purism test keeps the English locale 100 %
Latin):

1. Welcome · 2. Pages are `.eml` files · 3. Blocks · 4. Command palette ·
5. Themes, accent, scale · 6. Link graph · 7. Planning · 8. Project Knowledge
Engine · 9. Local AI (Co-Thinker, OCR, STT/TTS) · 10. MCP · 11. Import &
sync · 12. Finish.

The tour is *interactive*: steps with a **"try it"** button open the real
feature — the command palette, the appearance picker, the graph view, the
planning view, the integrations catalog, the MCP dialog, the FAQ. The tour
hides itself while the feature is in front of you and resumes from ⌘K with
its step preserved, so "try it" never traps you in a slideshow.

Behaviour:

- Auto-opens on a **genuinely first launch**; skipped/completed is remembered
  in `native-onboarding.txt` and never nags again.
- Reopenable anytime from ⌘K: «Обзор приложения / Onboarding tour».
- `--onboarding` CLI flag forces it (used by the screenshot pipeline).
- Gated out of `cargo test` app instances (the overlay would eat synthetic
  clicks) and out of `--snapshot` captures.

## OCR: verified fixes, not guesses

The OCR "won't start" report was re-investigated **against the mistral.rs
v0.9.5 sources** (the exact engine build CapsuleCraft ships):

- `mistralrs-core/src/vision_models/qwen3_5/` **exists at v0.9.5** — the
  architecture of Xiaomi-OCR-0 is supported; the earlier "unknown arch"
  hypothesis was wrong. The CLI shape (`serve --no-ui multimodal -m <dir>`)
  is correct too, and the processor config files are optional loaders.
- Which means the engine was panicking for a reason that was simply invisible:
  stderr was piped to `Stdio::null()` and the app reported only the exit code.
  That visibility problem is now fixed on three layers:
  1. **Preflight** (`ocr::preflight`) before spawn: model folder exists,
     `model.safetensors` / `tokenizer.json` / `config.json` are present and
     non-empty, `config.json` parses — failures name the file and the remedy
     in milliseconds instead of after a minute of loading.
  2. **Engine log tail**: readiness failures embed the last 12 non-empty
     stderr log lines directly in the UI error message.
  3. **`--isq` placement** moved after the `multimodal` subcommand — at
     v0.9.5 it belongs to the model-argument group (same struct as `-m`),
     pinned by a test.

The first real run on a machine where OCR previously failed will now show the
actual engine panic text in the error dialog — and the common broken-install
cases (truncated weights, missing tokenizer, corrupt config) are caught
before the engine even starts.

## Screenshots from the real app

The `--snapshot` CLI rendered every image under Xvfb against a generated demo
vault — no window-manager automation, no mocked UI:

- Regenerated: page (now showing a live task list with status pills), BM25
  search, planning (10 aggregated tasks with agenda buckets and due dates),
  graph, onboarding card.
- New gallery: `screenshots/themes/` — the same window in Nord, Gruvbox,
  Catppuccin, Paper and Rosé Pine.

To regenerate the vault: `cargo test generate_demo_vault -- --ignored`
(writes `/tmp/capsule-demo-vault`), then for each theme seed
`XDG_CONFIG_HOME/<cfg>/capsuleos/native-appearance.json` with
`{"theme":"nord",...}` and run `--snapshot screenshots/themes/theme-nord.png`.
